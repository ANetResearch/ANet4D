# 停车布局与道路连通的联合检查

这项通用机制针对“车位合法，但停进去会切断道路”的布局错误，不针对某辆车或某段地图。
借鉴 Claude 分支 `3f9fb60` 的 `ConnectedRoads`，保留本分支的活动、交通执行、运动安全后端。
实现使用 Shapely 扫掠包络与空间索引、SciPy 稀疏图强连通分量；没有新的逐人逐车脚本。

## 接入与边界

在 `life.driving` 中显式设置 `preserve_road_connectivity: true`，并使用 `curb_v1` 停车准入。
历史配方默认关闭，避免修改冻结候选的含义。先做相同输入的 plan-only 对照，再决定新配方是否启用。

1. 从绑定的驾驶图及真实车型尺寸构造静态边包络与索引。
2. 初始背景停车、居民家庭泊位、运行时目的地停车均检查道路连通。
3. 同一次提案预留多个停车姿态时，检查它们的联合占用；不分别假设另一处仍可绕行。
4. 活动运行时按当前停放、在途目的地和已预订目的地检查；自身原位置不当作他人障碍。
5. 合法性、地面支撑、几何避碰、行人通道、其他车主回程和真实出发许可仍独立检查。

本机制保护**原图中含至少两个泊位的往返分量内，现有停放占用后仍互通的车道节点**。
它不是全图容量证明，不保证单向通路、尚未核验的道路、不同尺寸车型或者已被旧障碍切断的分量恢复。
因此不能用此检查通过代替 feature 核验或连续运行验证。

相较来源实现补了两处通用语义：长边被阻挡不等于其远端节点被停车占用；
只有实际身体包络相交、且新失去出入边的车道节点才可按占用位置处理。
整个原有多节点分量也不能在排除节点后被判为“空集连通”。
多个预留泊位的联合检查避免互相把对方所在车道当成绕路。

## 成本与验证

包络与空间索引在场景初始化时构建；每次提案只查询命中的边，在稀疏图上检查连通。
运行期结果与占用快照共同失效，不按 10 Hz 为所有人重新搜索。
记录准备时间、检查/拒绝次数、图搜索次数和运行期检查耗时。不得预先宣称加速倍数。

比较同一真实环境、种子、150 人、40 辆背景车、30 名申请车主的两种初始布局：
全部背景车是否可摆放、共同可通行道路、接纳车主数、往返拒绝原因、耗时。
增加车主不是唯一成功标准：不能为人数损坏道路，也不能把规则更保守误报为真实容量不足。
只有准入改善且原有检查保持，才值得重录 25 分钟；新布局会使旧 query 绑定和见证失效。

本机制的测试覆盖单一路径、可绕行路径、已有阻断、远端节点、联合预留、居民准入，
以及运行中实际占用和预订变化后的缓存失效。真实场景完整运行证据仍需另行取得。

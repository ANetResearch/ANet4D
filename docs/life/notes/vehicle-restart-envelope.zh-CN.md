# 行程车辆的临时停车与行人避让

来源：[X 原样复现 V](../audit/registered-town-x/README.md)。车辆已获得通行许可，
但持续有行人进入其起步所需的额外间距；不能把它归因于未获路权、车位不足，
也不能只提高 60 s 停滞门槛。

`30d7f7c` 在 LifeEngine → Crowd 接口增加 `vehicle_intent`：只标记正在执行
已准入行程的车辆，包含因行人临时停下的车。已停泊车辆、未准入出发请求、
下车的人和行人恢复动作不获得该标记。没有伪造未来加速轨迹或修改行驶路权。

车辆与行人共用同一基础间距和速度相关间距参数。行人速度候选预测保留临时
停车的起步范围，避免把暂时停下的车当作静态陈列物，反复贴近穿行。已处于
该范围内的行人继续使用现有接触安全逃离规则，不能突然以新间距把它锁住。
离开后再按正常范围规划。这是局部预测规则，独立的实际联合碰撞、地面支撑、
加速度检查与原门槛不变；也不声称所有社会间距都是每帧硬约束。

开发中试过强制既有间距逐帧不减，因行走姿态改变会把无碰撞的行人锁在车旁，
被回归测试拒绝。最终实现没有采用这一规则。

44 项相关测试通过；另补充回放测试确认车辆意图能与失败帧一起保存和恢复。
合成镇区 3 名司机、8 名步行居民的完整 1500 s 对照，两种模式各完成 44 段
驾驶，逐 tick 碰撞/加速度检查通过，修正后也未发生路由失败。单次墙钟约
14.12 / 14.35 s，包含的是该合成运行，不含原生渲染或真实场景编译；这一
对照只说明未出现明显成本跳升，不能外推真实性能上限。见
`../audit/vehicle-restart-envelope/` 的脚本和原始统计。

仍需在 X 同一冻结真实环境重新运行完整 25 分钟。它不解决所有行人路权、
连续穿行流的公平性、站立活动占用车行道或路网错误；若出现其他失败，须按
实际证据区分，不把所有问题归因于这一处间距差异。最终 query 和在线发布
仍等待完整场景与相机验证。

# 生成多样活动需求，再验证可执行性

2026-10-25 用户恢复开发后的活动层接口。它服务于测试床的多样性，不以居民总出行时间最短为目标。
道路正确性、交通控制和任务验证仍是各自必须完成的层；本策略不会替代它们。

## 四层责任

1. **环境 feature**：给出同坐标版本的真实可行驶面、车道、路口、步行区、泊位与接驳。核对系统偏移、实际路宽和连通性；不可把错配导致的拒绝称为容量不足。
2. **活动需求**：按配方/种子生成角色需求、活动地点和方式偏好。既可以开车，也可以步行、停留；不要求选最快方式，不依赖录制终点、query ID 或逐人的轨迹脚本。
3. **执行**：运动后端负责真实支撑、车身碰撞、行人让行、车辆跟驰和路口冲突。短时冲突应由局部交通交互处理；不能把所有相交完整路线永久串行化后称为自然车流。
4. **场景任务**：用独立覆盖层调整外观、公开区域和事件条件，验证四类七意图；完整视觉对象集合、可见性、成功与质量评分不能由行为日志代替。

Claude 的截图指出局部中心线偏差、停放车切断通道及整程走廊串行化。这些作为待核对的问题来源，不直接当作本分支已验证的数字。只读核对到 `7c74ffc`，服务器正在使用 `tmp-drive/code51` 编译 r6 驾驶图。该工作应优先在输入和执行层闭环，Codex 此次不叠加另一套道路修补。

## 通用活动策略

将 [配置](../../configs/activity-selection/diverse-feasible-v1.json) 的完整对象放入：

```json
{
  "life": {
    "activity_engine": {
      "selection": {
        "kind": "diverse_feasible_v1",
        "mode_weights": {"walk": 1.0, "car": 1.0}
      }
    }
  }
}
```

这只是配置片段；环境和 driving map 仍须由正常接入契约提供。`modes` 未启用驾驶、没有车主/车辆时，不会凭该字段创建车辆或驾驶资格。

- 每次新决策依据 seed、actor、decision 序号生成带权的方式顺序。权重表示需求分布，**不是完成比例或车流配额**。当前配置同等权重，作者可调整。
- 活动设施按需求紧迫度、活动权重和确定性随机优先级排序。相同设施的多个站位共享同一随机优先级，不因站位多获得更多抽签机会。
- 先找首选方式中的可行活动；如果所有当前候选均不可行，才尝试备选方式。不截断成固定 top-k，最近站位失败时仍检查其他站位。
- 该策略在设施和方式选择时不按旅时降分。旅时仍用于开闭时间和返程约束；同一活动的接驳泊位仍由已有路线逻辑选择，底层路径长度优化不是全局活动方式优化。
- 目的地资源、实体所有权、上下车、返车/返家、合法路线、完整活动步骤的实际完成检查全部保留。强制返家需求优先于新活动偏好。
- 有界分支剪枝按“方式优先级、设施优先级”工作；不为说明选择原因额外请求路线。每次决策只做少量哈希排序，不在每个物理 tick 重规划。
- `activity_selection_policy` 记录首选顺序、实际选择及是否使用备选；既有 `activity_choice_evaluated` 保留实际尝试、拒绝与已评估方案。被剪枝的候选不能声称不可行。

未设置 selection 的旧配置保留历史 `travel_utility_v2` 行为用于复现。**新版 demo 候选应显式启用 diverse_feasible_v1**，不能仅修改文档却继续用旧录制。没有原地修改已冻结的 J/M/P 输入。

## 验证和整合边界

代码位于 `chimera/civil/activity/selection.py`；Director 增加独立 selection 参数，GroundedActivities 将配置透传。没有改变碰撞后端或行驶准入。

局部测试检查：较慢但合法的驾驶可被选择、不可行驾驶回退步行、无路线时不泄漏预订、容量/开闭时间/返家不被绕过、设施重复站位不改变选择、剪枝与穷举一致、种子与前缀稳定、walk-only 适配器不凭配置获得驾驶能力。

合成小镇诊断使用已有 LifeEngine 和闭合道路、泊位、行人避让、上下车；打开新的选择字段后才给车主 walk/car 两种活动方式。它验证跨层接线，不证明摄影测量环境的 feature 或真实容量。运行结果见 [证据](../audit/diverse-selection-v1/README.md)。

与 Claude 整合时保留单一 Director：接入 selection API，避免重复引入另一套活动调度器。其 `in_vehicle_time_factor` 可用于旧效用策略，但不应再成为新版多样活动策略的跨方式排序依据。其道路/停车通路证明及交通后端需单独回归，本补丁不自动转授它们的正确性。

恢复后的验收路径：同版本 feature 审查 → 真实小规模混合活动与交通交互 → 按实测容量扩展至 25 分钟 → 任务覆盖层 → 七条相机与评分见证 → 在线展示。不能以单车短程通过、统计移动数或合成小镇成功代替最终场景验收。

方式权重允许只覆盖需要调整的方式，例如纯步行配方可写 `{"walk": 1}`。
未填写的权重采用中性值 1；它们只描述偏好，不开启驾驶能力。是否有车及可用后端仍
决定实际候选方式。所有显式权重必须为正有限数，未知方式仍拒绝；旧的完整权重配置
保持原有确定性排序。此项修复来自第二环境 DC 的配置失败，不更改世界或生成规则。

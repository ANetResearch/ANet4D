# 通用活动引擎候选 activities_v1

本分支加入可运行的活动决策模块，而非逐实体编写未来轨迹。此文随验证结果更新；拓扑测试不构成生产磁带准入。

## 实现边界

- `chimera/civil/activity/director.py`：角色、活动需求的复发周期、设施开放时间、容量、交通方式与资源占用；只有到达并完成停留后才满足需求。决策与录制长度、query 无关。
- 活动完成后再选择下一项。固定 seed、实体 ID 独立随机流、确定顺序可重放；不是调用 LLM 驱动 NPC。
- 通用驾车状态链：走到自己的车门→上车→驶入目的地泊位→下车→步行到设施→活动。需后端提供可达路线、车门位置及可返回的有向车路；不能把路中点当泊位。
- 设施和泊位先检查再原子预留，旧位置由真实离开观察释放。到达、停稳、服务时长和人车会合由仿真后端的观察确认，不相信 agent 提交的状态。
- `grounded.py` 可通过 `life.behavior: activities_v1` 启用运行时行人活动；保留已有实际身体、支撑、碰撞、转向、让路及生命周期审计。
- **真实镇区的居民车辆仍使用 curb_v1**。该地图尚无验证后的居民人车归属、车门及往返泊位网络；通用人车链目前只在拓扑后端验证。配置非步行模式会明确报错，不假装完成三维上下车。
- 建筑入口未验证，设施访问仍明确表示为室外等候/休息，不声称进入室内或坐下。

## 成本与真实性

活动决策只在完成、资源重试等事件发生时执行，运动检查仍逐 tick 执行。目的地选择先生成确定的候选权重，再按可证明的收益上界逐个精确寻路：只有剩余候选不可能胜出时才停止，避免固定 top-k 遗漏可达地点。声明的后端最大速度用于旅行时间下界，实际路线若违反速度上界会报错。测试将剪枝结果与完整穷举逐种子比较，结果和随机流一致。静态路径缓存上限 4096 条，包含不可达查询；停车改变静态可走空间时失效。动态行人和车体仍交给实时避障，不用静态缓存代替安全检查。

`activity-profile.json` 分开记录决策耗时、静态路径搜索/缓存、局部 guided_route 耗时及模拟总耗时。决策时间包含静态寻路；guided_route 只是局部导航的部分；不可把嵌套时间相加，也不能把剩余时间全部称作物理计算。计时不参与决策和确定性事件摘要。

其他构建的剖析显示频繁局部重规划占主要时间，此模块并未替换其 Python A*。后续优化应按相同配置比较重规划次数、搜索扩展数、tick 延迟分位数及完整审计；不得通过减少身体检查或掩盖停滞提速。

同 tick 并行规划应读取同一快照、确定性提交并统一裁决资源冲突；本版保持串行确定性提交。诊断快照只能复现失败，不能拼接跨代码版本轨迹冒充完整构建。

## 快速运行

```bash
python -m awr.life.civil.activity.headless \
  --config scenarios/activity-engine-v1/network-a.json \
  --out /tmp/activity-a-fresh --duration 1500 --seed 17
```

`network-b.json` 更换路网拓扑，沿用同一活动规则。可替换人口、设施、交通方式与开放时间，无需改实体脚本。该后端只有拓扑运动：**没有碰撞、轮胎支撑、车门动画和相机**；所有结果均标记 `admitted_for_benchmark: false`。其毫秒级运行时间不能外推为真实三维场景性能。

真实场景候选：`scenarios/activity-engine-v1/town-candidate.json`。保留正式请求人口与门槛；不能因几何容量不足悄悄减少人口。用原 grounded CLI 在新版本目录运行。未通过审计不发布为 benchmark 磁带。

## 产物与失败

- `activity-decisions.jsonl`：活动选择、动作完成、需求等待和失败；不混入原有 `activity-events.jsonl` 运动事件。
- `agendas.json`：仅初始活动加上已经实际选择的活动，兼容原有行人审计。
- `activity-profile.json`：性能数据。
- `*.activity-failure.json`：无法继续时的状态、资源及事件诊断。
- 已有全量物理/生活审计仍是发布条件。无需求时可以明确在家停留；有需求却无法找到可行活动的等待计入 `unscheduled`，不能标成成功服务。
- 源码指纹递归包括新子包，防止活动代码变化未进入构建凭证。

## 验证记录

单元/回归、两图三种子重放及录制长度前缀一致性见 `docs/audit/activity-engine/`。真实场景录制与在线预览的结果另行附录，不能由拓扑测试推定已经通过。

拓扑诊断的单容量设施允许最长 600 s 的显式需求等待（另一居民可能占位数分钟）；真实镇区仍使用原 120 s 失败上限和生活审计，未用该诊断设置放宽真实场景门槛。

## 真实场景集成中发现的行为问题

首次 activities_v1 短段在仿真 40.4 s 被拒绝：person-021 有已到期但无法出行的需求，而其他可选活动还没到硬性周期阈值，造成无意义地等待。决策现采用软需求：默认到周期的 50% 即可候选，随需求程度连续加权；不可达需求仍保留，不冒充完成。若所有成熟候选均不可行，原 120 s 连续失败上限仍生效，等待仍计为 unscheduled。新增回归保证“先做可行的近期活动”不会清除尚未完成的迫切需求。

车辆在活动模式下也不再按录制窗口均匀摊派出发：使用独立实体随机流，按持续停车活动的稳态长度偏置抽样得到当前已停时长与剩余时长。输入没有录制时长，也不依赖车辆名单排序。该适配器仍只有已验证的向外路边行程，不能当作完整居民司机循环活动引擎。完整镇区适配还需合法返程拓扑、司机归属和上下车证据。

静态连通域预筛在空间变化时重建，并缓存同一出发点的候选连通域。它保留实际规划器允许尝试的全部源连接点，只排除无法连通的候选；精确连接线、身体间距与 A* 仍由原规划器验证。回归覆盖“预筛不得拒绝原规划器可走路线”及停车切断通道后缓存失效。

### 地方活动可达性

人口生成时，住宅室外起点必须能往返至少三种活动设施（`min_activity_kinds`，地图可配置）。每种活动保存精确往返路线证据；居民只产生当地已证明可达的活动需求。不能把仅连到咖啡馆的起点分配为具有全镇所有需求的居民，也不能在运行中删除困难需求来掩盖失败。必要的返家路线不受普通休闲行程偏好距离限制。

## 混合车辆需求与停车场

完整扩容目标见 `activity-demo-goal.zh-CN.md`。车辆总量允许由行驶车、路边停车和停车场停车组成。`life.vehicles.population` 用 `curb_trip`、`curb_parked`、`lot_parked` 三个非负整数声明需求，三项之和必须等于 `vehicles`，不能与旧 `trip_share` 同时配置。分配按此固定次序；追加停放车不会改变原有行程车辆 ID 或其随机出发需求。任何一类缺额均拒绝构建，不静默换成另一类。

`parking_lots.py` 从 `semantics.verified_parking_regions` 生成停车排中的泊位，和旧的合成 `parking_lots` 分开。每个区域需要唯一 `id`、`verified: true`、非空调查证据 `evidence`、`polygon`、`aisles`、`entrances` 与 `rows`。入口须接触区域边界并连到通道；各通道与入口组成连续区域。每排描述泊位中心线 `start`/`end`、`spacing_m`、车身朝向 `heading_rad` 和沿车身轴到通道的有符号距离 `access_m`。坐标单位米，朝向单位弧度。

每个候选同时检查车身、轮胎支撑、停车规则、停车区域边界、车道禁占、直线泊位出入空间及与其他车的冲突。正式构建还检查行人通道不能被截断。车位出入走廊持久保留，不能用另一辆停车填上。倒出时保持车身朝向，不因路线切线反向而旋转车体。

这只支持经过验证的**长期停放车辆**。泊位到通道的直线支撑检查不是停车场到道路的完整连通证明，也不是实际驶入/驶出记录；当前证据明确写 `road_connection_verified: false`。动态停车场车辆必须另行验证转弯、道路连接、资源释放和司机行为后才能接入，不能复用静态泊位假装已支持。

`scripts/check_curb_capacity.py` 同时报告三类请求/接纳数和缺额原因。它不考虑完整行人占用与时序，只是录制前筛查，输出始终标记 `release_evidence: false`。当前真实镇区没有已标注停车区域；因此提出 `lot_parked` 需求会明确失败。单元几何夹具的通过不代表镇区已容纳百辆车。


## 2026-10-23：真实行程路线与出发预留适配层（尚未接通 grounded 执行）

`chimera/civil/activity/driving.py` 增加 `DrivingRoutes`：把实际尺寸车辆的候选
图转成 Director 可调用的 `Route`，按每条边原有许可区域重新核验完整车身、
轮胎支撑和转向。接口只匹配精确泊位；坐标相同但朝向有歧义的泊位会拒绝，
不会最近点吸附。长期停车与正在行驶的车辆使用完整、显式更新的占用快照；
旧分配中的 blocker ID 不再被误当成永久障碍，也不能通过漏报实体移除障碍。

计划不等于出发许可。活动选定后，出发前还要重查当前占用，原子预留整个
行程的道路资源和扫掠走廊。命名不同但几何相交的路段也会冲突；不相交且
不共享资源的行程可以同时获得许可。预估时间走完不会释放道路，实际车辆
停在目的泊位且朝向正确后才释放。现阶段整段行程预留比较保守，尚不能用
它宣称交通吞吐已经满足 30 辆要求。

`nominal_at` 给出带加减速、转向限速、换挡停车的名义运动采样。它不是实时
避碰控制器，不可通过冻结一个高速运动采样来模拟急停。后续 grounded 适配
仍须保留逐步车身冲突/支撑检查、驾驶员步行与上下车、动态泊位/行人通路
更新及真实到达确认。本轮不改线上磁带，不将模块测试称为完整活动验收。

相关回归共 49 项通过（activity_driving、activity_engine、street_returns、
maneuver_search、driving_graph、driving_motion）。真实场景依然欠缺 30 辆完整
驾驶员活动链以及 25 分钟证据；最终门槛没有降低。

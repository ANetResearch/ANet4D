# Drone4D 环境 feature 接入原则 v1

2026-10-25 用户确立的规范性接入契约。自动验证器与统一数据 schema 仍需实现/对齐；本文不是已完成接入的声明。当前任务见 [长期目标](../history/activity-demo-goal.zh-CN.md)。

## 原则

**先描述并核验环境实际允许的行为，再生成活动。** 后续任何 Drone4D 场景使用本引擎，都必须提供基础 feature，并为声明的行为能力提供相应条件。允许自动提取、人工标注或数据转换，但须有来源、版本与验证证据。

确定性 feature 指运行内冻结、可复现的环境定义，不表示标注天然正确。精度和未知区域必须说明；不能凭“看起来有路”推断通行，也不能把粗网格误拒绝当作物理不可行。

## 必需的基础 feature

| Feature | 必须表达并核验的内容 |
| --- | --- |
| 坐标与时间 | 单位、坐标轴、变换、高度基准与时间约定；渲染、导航、实体及评分可对齐 |
| 几何与支撑 | 可支撑表面、障碍、边界及未知区域；重建、碰撞/导航代理对应，简化误差明确，不虚构地面 |
| 区域语义 | 稳定区域 ID、边界、用途、允许主体/活动与限制；公园不自动等于停车场，屋顶不自动等于道路 |
| 通行能力 | 所支持主体的通行空间、连接、出入口、方向、净空及地形约束；局部可站立不等于完整可达 |
| 实体能力 | 稳定身份、模型/尺寸、运动模式与必要运动约束；视觉与占据空间一致，一个后端负责一个实体的位姿 |
| 资源与容量 | 站位、入口、瓶颈等资源及占用/释放规则；容量声明有依据，候选数量不能冒充联合运行容量 |
| 版本与能力声明 | 环境、资产、语义、适配器版本/摘要；支持、不支持、未知的能力及原因；变化使相关缓存/验证失效 |

人口、角色、偏好、需求和随机种子属于独立生成配方。动态占用与活动属于运行状态，不能通过修改冻结的环境事实为冲突开后门。

停车布局必须与通行网络联合核验。可停放的几何位置不能自动成为可用泊位；
背景停放、家庭泊位与运行时停车均需说明其对道路、行人通道和其他主体出入口的影响。
拒绝原因须区分既有网络不通与新布局切断，不能把布局失误称为环境容量不足。
当前实现及明确范围见[停车保路检查](parking-road-preservation.zh-CN.md)。

**通行许可与持续停留许可必须分别表达。** 可以走过横道、道路或停车通道，不意味着可以在那里生成住处、设施等候和长时服务站位；导航成本也不能替代用途许可。真实场景网络现提供独立 `standing_free`，候选编译与运行时站位共用它，仍需实际身体净空、资源和语义验证。未知停留空间应报告缺失，不以低路径成本推断可停留。见 [真实失败与整图核对](../audit/junction-mixed-failure-v1/README.md)。

## 按能力追加必要条件

**泊位是行程端点，不能作为道路捷径。** 停车通道若允许穿行，应独立标注为道路或车道，
不能借用泊位的进出连接模拟通行。精确寻路、缓存树、活动筛选、往返准入须共用此语义。
结构连通分量仅作为候选上界：经另一泊位连接的图不证明车辆能往返。
真正准入须在当次支撑、许可和占用条件下验证双向可执行路径；改变这些语义后旧容量
与运行报告不能自动继承。

未声明、未使用的行为模式不得成为其他模式导出的隐含依赖。例如纯步行包可以缺少车辆导航；录制中有车辆则必须绑定车辆导航。缺失能力应明确记录，不能伪造导航摘要、用人的图替代车的图，或把无车辆时的空检查当作交通通过。无主体的单体统计显示不适用，不能伪填零值。

| 声明能力 | 必要 feature |
| --- | --- |
| 行人目的性活动 | 合法起点和步行空间，所需目的地的用途、入口、站位/容量和停留规则；室外活动不强制虚构室内模型 |
| 车辆通行 | 真实道路走廊/车道、方向与连接、转弯/会车空间、路口规则及适用车型；无红绿灯仍需处理让行 |
| 停车与反复出行 | 合法区域/泊位、连续进出路径、停车后剩余通行空间、占用/释放规则；不能在行车道直接结束行程 |
| 驾驶者活动链 | 人车绑定、可步行到达且车体净空合格的上下车接口、状态转换、目的设施接驳及停车资源 |
| 边界进入/离开 | 合法出入口及生命周期规则；场内运动不能用突然消失代替离场 |
| 特定设施活动 | 对应设施真实用途、区域、入口与容量；缺少设施时不生成依赖它的活动 |

无车路的环境可支持已核验的行人活动。缺失或未知条件应明确报告不支持/未验证，不能由引擎猜测补路补设施，也不能静默把失败行程改成永久停车。真实容量不足可调整配方；错误标注、实现误拒绝则需修正，不能用降配掩盖。

## 标准接入流程

1. **导入：** 环境适配器转换数据，检查 ID、引用、坐标与版本；核心不新增场景特例。
2. **核验：** 对照真实重建、语义和资产，区分数据错误、缺失、未知及真实限制。
3. **评估：** 计算主体—区域—资源—活动可行关系，审计联合占用与交通冲突；分别标明候选、静态验证、动态实测和上界估计。
4. **准入：** 按能力接纳配方，记录请求/接纳差异、原因与替代方案，不静默降配。
5. **验证：** 使用同一引擎检查连续性、合理停留、恢复、资源释放、确定性及成本；几何通过不等于长时高密度已通过。

接入产物必须包括规范化环境包、feature 验证报告、能力清单、容量证据、接纳配方及绑定其版本/摘要的运行记录。新环境复用流程，不逐个主体编写完整时间轨迹。

设施候选编译也必须绑定道路使用策略：是否允许共享街道、网格步长及候选主体尺度需显式记录。新支撑层不能直接沿用旧站位的组件标签，禁止把“预编译按人行道、运行按共享街道”的差异解释为真实容量限制。通用入口 `scripts/envpack/compile_outdoor_places.py` 已支持重新生成室外候选、记录来源与拒绝项；构建器拒绝新文件中的道路策略/步长与运行配置不一致。候选编译中的保守主体尺度不替代运行时实际资产的支撑、净空和资源准入，室外接近点也不能冒充真实门或室内能力。实证见 [路口支撑与站位编译](../audit/junction-support-review-v1/README.md)。

## Query 层约束

环境能力与任务可解性分别验收。覆盖层可策划外观、身份、目的地、偏好、事件先后关系和干扰者，必须遵守真实 feature 与资源；不能虚构道路、缩小主体、瞬移或根据 agent 回答修改事件。

需要识别车牌等模型细节时，能力声明必须区分“已建模/有真值”和“在实际相机下可观察”。
整车检测框、投影角度和名义像素尺寸不能代替细节表面的可见性；须考虑自身与外部遮挡、
实际主体姿态及曝光相机，保留 RGB 对照。细节可见也不自动证明字符可读或任务可完成。
这项能力按任务需要追加，不作为纯步行场景的隐含依赖。
[原生车牌表面诊断 DM](../audit/plate-surface-dm/README.md) 提供初步机制证据，尚未完成任务接入。

任务层追加公开区域定义、目标属性/身份及事件真值、可观察外观/车牌、相机与控制能力。通过公开接口确认可见性、分辨率、可操作性和时间条件；后台知道答案不是可解证据。评分按任务类型复用。

公开 query 区域应作为固定场景输入，不能随本轮目标轨迹、种子或录制时长自动漂移。新增 `public_regions` 覆盖层绑定世界/语义摘要，显式区分原始场所多边形与人工搜索区域；后者不授予土地用途、通行或停车许可。[固定公共区域实现](../audit/public-regions-v1/README.md) 保留旧布局作为一次性的作者选择，后续构建不再依赖主体活动范围。区域定义通过不等于任务可解。

## 精度、成本与实现状态

### 使用原始动作资产时的附加条件

动作资产和行为意图不能混为一谈：具有坐姿动画不等于环境有可用座位；具有行走循环不等于完整路径可达。
接入成熟动画能力的环境还须提供其实际使用的地面高度/接触条件、设施作用点及朝向、可接近空间、
占用规则和主体尺度。缺少条件时不声明相应活动能力，不靠视觉摆放伪造完成。

导航、角色控制与动画必须明确谁拥有世界位姿。使用根运动时应记录位移/朝向的提取约定，避免重复转向、
循环位置重置或把竖向身体动作重复叠加到世界位置。环境地形绑定须显式记录来源；
根节点在地面上不能替代足底接触、完整碰撞及可达性验证。原始艺术动画的根曲线也不自动等于运动学合格轨迹。
初步实现与证据见 [动作执行记录](../research/route-b-motion-execution-2026-10-27.zh-CN.md)。

精度由行为可信度及 query 需求决定，声明误差与验证范围，不默认要求特定物理引擎、960 Hz 或厘米级捕获。简洁后端同样须满足连续运动、转向、支撑、遮挡/身份及停车合理性。

静态 feature 编译后按版本缓存；运行时处理动态资源与必要局部规划，不因短暂受阻反复无界重算全图。活动、规划、运动、审计及渲染分别计量。

下一阶段将本原则对齐到实际环境包字段和验证器，输出当前场景差异清单。**文档确立不等于验证器已实现，feature 合规不保证任意人口或任意 query 都可运行。**

当前首版 [盘点工具与证据](../audit/environment-features-v1/README.md) 已实现来源绑定和部分结构检查；其明确保留语义、联合容量和渲染为待验证，尚未成为完整运行时准入契约。不得把盘点的结构一致直接用作场景发布许可。

活动语义字段已首轮落地：`Place.affordances` + `semantic_source`、`Activity.requires`，目的地选择和能力测量共用约束。只有明确来源的条件才可授予；未知不默认支持，旧空约束规则标为未约束。见 [实现、数据审计与复现](../audit/place-features-v1/README.md)。这一必要条件不能替代 feature 内容核验、空间可达性与联合容量验证。

场景需求通过可选的 [声明式活动规则](activity-recipes-v1.zh-CN.md) 与 feature 分离：新设施类型可接入规则，
但活动配置不能授予地点能力、指定人物轨迹或改写测得的停留空间。需分别保存需求规则、语义覆盖、
实际选择与完整执行证据；没有可行选择不等价于真实容量不足，亦不能用配置的活动数量冒充执行多样性。


2026-10-25 新增 [七类 feature 静态诊断器与真实数据对照](../audit/envpack-integration-v1/README.md)。`awr.life.envpack.validate` 支持明确的派生 `road_graph`、输入摘要和只读测量，但所有结果均 `admitted=false`。旧运行不授予当前能力；路图、支撑、设施和下游通行缓存须绑定同一坐标版本。道路中心线比例、无向图连通长度、停车中心点检查均不能独自证明路径、停车合法性或联合容量。该诊断器尚未替代运行时环境准入。


构建入口现已加入 [输入绑定及候选规划检查](../audit/registered-preflight-v1/README.md)：CLI/config 消费的 world/support/semantics/places/lane_network 必须与 v2 包相符，并验证已声明文件摘要；核验包与运行输入不能各用一份。v1 历史可选层未声明时显式标未绑定。v2 尚无完整发布准入；可用 plan-only 核对初始规划，或显式 --dynamic-validation 做不发布的动态验证。两者均保留输入绑定；验证模式也保留运动/行为检查，产物标记为诊断，任务与网页准入拒绝使用。绑定与放置通过不代表动态容量或任务可解。室外形态 `public_open_space` 不覆盖土地用途 `kind`，未知用途不能推断成公园。

派生层必须声明其来源，例如 `layers.driving_map.built_on.support`。来源与当前包冲突时，即使派生文件自身哈希正确，也不得用于本包规划；能力应标未知，不能推断为真实容量不足。构建绑定已拒绝显式来源冲突，诊断报告亦传播该状态。路径一致只是一层约束，内容来源仍需编译输入摘要、几何和动态复核；见 [车辆图与来源检查](../audit/registered-driving-v1/README.md)。

联合停车的最低接入要求：单个泊位合法且有进出曲线不足以声明居民驾车能力。须在实际初始背景占用和全部接纳车辆的联合布局下，保留出发、设施停车/步行接驳及返回机会；新增车辆不得封死已有车的唯一通路。接纳报告应区分原始图不连通、静态遮挡、步行接驳缺失和动态执行失败。保守布局得到的是可行解，不是容量上限；运行中仍须复核动态占用。首轮实现及实际证据见 [联合停车准入](../audit/joint-parking-admission-v1/README.md)。

## 停车状态与通行空间的一致性

可移动车辆不能永久当作固定地形，也不能在停放时对路线规划隐形。环境适配器须提供真实车身尺寸、朝向、停车/行驶状态，以及不含这些可移动车身的基础步行空间。运行时在停放状态变化时更新通行几何和相应路径缓存；活动决策、能力测量与执行采用同一快照。实时运动安全检查继续作用于所有车身。实现应按状态变化更新，避免每个 tick 重建静态路由器。

驾驶活动的步行接驳还须检查**本车占用目标泊位之后**的空间：将车身从原泊位
移至候选泊位，保留其他已停车辆与固定障碍，确认下车点到设施的完整路线。
空泊位旁能站人不等于停车后能走出；反过来，也不能继续把已腾空的原泊位
作为障碍。检查不得移动下车点、缩小车身或改变真实地面。这个通用条件只
证明当前占用条件下的候选接驳，后续动态交通仍需执行层检查与完整运行验收。
见[九次真实停车的对照](../audit/parking-transfers-ae/README.md)。

**活动规划证明必须能交给执行器使用。** 后端已验证的连续步行路径不能
只留下“可达”的布尔值或丢失几何的编号。当前活动应持有不可变路径，执行
前对实际地面、停放车身及连续连接段重新检查；有效则执行，失效才重新规划。
动态停车使粗网格节点断开，不等于此前连续路径已经失效，不能再次用较强的
离散连通性预筛选否定有效证明。此规则不授权忽略新增障碍、吸附坐标或跳过
运动安全。实景反例与通用交接实现见 [AV](../audit/walk-handoff-av/README.md)
及 [AX](../audit/walk-evidence-ax/README.md)。

接口的真实坐标与规划离散化须分开：车侧上下车点、设施入口等是连续空间的接口，不能只因
所在栅格中心被动态车身挡住就宣称不可达。允许用经过完整地面和身体检查的连接段接入
规划网络；不能将接口吸附移动、跨越禁止地面或忽略实际车身。起点和终点使用一致规则，
连通性预筛选不得比实际路径规划更严格。见 [实景入口对照与完整静态路径](../audit/runtime-access-t/README.md)。

**执行空间与规划节点空间必须有明确的接入契约。** 路网/步行网格的内缩
节点掩码不能自动等同于物理禁行地面。适配器应分别声明未内缩的许可空间、
支撑/障碍和派生规划节点，并说明执行器实际可到达姿态如何重新接入规划。
合法姿态的接入仍须验证连续支撑、身体/转向净空与障碍；不得吸附瞬移、
直接放开未知地面，或把所有内缩边界误拒绝归为真实容量不足。
[AH 对照](../audit/traffic-integration-ah/README.md) 暴露了这项缺口。
[AI](../audit/navigation-domain-ai/README.md) 增加最长 1.5 米的物理连接证明：
适配器须提供未内缩许可区、规划身体半宽和整个扫掠足迹的支撑证书。
缺少其中任一项仍拒绝；不得仅在端点或圆环采样就忽略足迹内部的支撑孔洞。
节点图、额外禁行限制、路径成本和实际车身检查保持生效。该规划半宽并非
完整姿态动力学证明，转身及实际身体运动仍由原执行器检查。小场景两种种子
已通过，真实环境仍须完整验收。

标注道路中心线也不是唯一允许的轨迹。若实测支撑、映射道路宽度和通行许可允许，可以
自动生成连续偏移的车道候选；每个候选仍须以实际车型复核支撑和转向，连接节点还须
单独验证连接曲线。重叠候选只是不同驾驶方案，不是额外车道或新增容量；实测对照须报告
去重覆盖、实际连接与动态执行，不能仅以候选数量评估改进。见 [可选实测车道生成](measured-lanes-integration.zh-CN.md)。

## 需求与容量证据不能相互替代

场景允许某种交通方式与生成器偏好该方式是两回事。不能因为时间效用模型选择步行，就认定场景没有驾驶能力；也不能因需求生成器提出驾驶意图，就认定道路可执行。分别记录原始道路/泊位连接、静态及动态拒绝、候选方式与最终选择、实际完成活动。

几何错配、道路宽度标注与联合停车对通路的影响，应先做系统性对照，不能一开始按真实容量不足归档。完整路线相交只是潜在时间冲突；若执行器采用全程排他许可，必须标记为后端保守限制，而非地理上无法共存。多目标交通所需的局部路权、跟驰及人车交互须在执行层验证。

## 运行证据与活动验收

车辆活动的接入数据须提供稳定泊位 ID、姿态、停车合法性及来源。运行记录须能够连接意图、驾驶者、车辆、路线变更、实际出发和停车，并在磁带中保留车辆身份与乘员容纳关系。仅声明“已到达”不能代替观测证据；两套事件账都缺失时，仍须从磁带发现未被解释的车辆运动。

完整有效车程由意图、实际移动和合法到达证明，固定的 50 m 或 30 s 不是任意场景的接入条件。短途可以真实，尚未结束的行程只验证已录制区间，不能计作完整到达；车辆到达也不等于驾驶者已完成后续设施活动。连续活动、长时停滞、几何安全和任务见证分别验收。验收规则变更必须显式版本化，保留原配置及失败报告，不修改已有磁带。实现与原生对照见 [BX](../audit/journey-evidence-bx/README.md)。

## 自然区域、规划候选与可执行空间分别表达

OSM 道路中心线或公园的自然边界并不承诺整条线、整块区域都可执行。环境包须分别保留原始语义、实测支撑与禁止/未知区域、派生可行路线及候选活动地点；活动能力按后两者和实际执行证明声明。全区域覆盖率用于发现数据缺口，不能单独替代可达性、共同容量或整个环境的准入判断。

粗分辨率质量图中的水体/孔洞标记与精细实测支撑冲突时，应记录冲突范围、候选地点和运行轨迹的暴露，再核对几何与用途。不能仅因比例很小忽略，也不能仅凭标记推定伪造地面。历史目录或容器路径迁移须以实际消费层的内容摘要证明等价，不能靠重写路径通过核验。当前候选的整场实测与未解决项见 [CS](../audit/candidate-feature-cs/README.md)。


## 观测侧使用的静态 feature 与单位契约

用于飞行高度、云台瞄准和像素地理定位的公开地形层也须记录实际来源、坐标、
分辨率和摘要，不能因某机器存在旁路派生目录而悄悄换层。派生层须追溯到
当前世界的源文件；分辨率更高不自动意味着测量更正确。验证可解性时应分别
检查目标可见/身份、公开地理投影误差和位置报告契约，不把定位失败描述成认错人。

传感器外参、角度单位、噪声单位和采样时间必须与物理渲染一致；对照采用同一
世界和任务，保留旧失败证据。[CW](../audit/gimbal-units-cw/README.md) 是实例：
2 m/10 m 地形离线对照未解释定位失败，随后确认云台编码器度/弧度误用。
修正单位属于实现错误修复，不是为让 query 通过而调低噪声档或放宽位置半径。


## 道路服务与候选轨迹的区分（2026-10-26，设计约束，尚未替代运行规则）

一条真实道路可以有多条相互重叠的候选轨迹。停车后某条轨迹失效，不等于整条
道路不能通行；反过来，同一道路 ID 仍有节点存在，也不能证明入口、出口或路口
方向连通。DE 整图诊断仅揭示这种表示差距，不授权放宽当前保护器。

后续道路服务层必须绑定实测几何/许可层和候选图摘要，表达有方向的道路接口及
需要维持的连接。接口来自注册后的真实道路端点、路口和合法边界出口，不从
“让当前停车方案通过”反推。不同候选姿态可属于同一接口，但不得凭分组产生
不存在的连接边；每条连接证明必须落到连续、物理已核验的实际路径。

停车前后比较同一组服务关系，分别记录保持、切断和无法判断；原本不存在的
连接不得当作本次停车造成。始终保留实际在场车辆的出发/目的地/返回接入证明，
不能只保住道路主干而困住某个已接纳车主。泊位仍是端点，不能当作道路桥梁。
车身、转弯、地面、合法停靠和行人接口检查继续独立成立。

验证顺序：先验证接口来源与分组，再用相同占用对照全图，再检查联合停车和实际
驾驶链，最后完整录制。必须包括双车道有真实绕行、单车道真切断、反向通行缺失、
路口转向丢失、泊位假捷径、整个分量消失与已有车主失去接口的正反例。
不能按道路标签或“损失节点少于某比例”放行，也不按接纳人数选择规则。
见 [DE 完整候选证据](../audit/parking-topology-de/README.md)。

验收门槛也须声明能力范围：构建入口已对居民驾车证据门槛核验后端、驾驶模式和
地图绑定，缺失则在加载几何前报错，不再耗时录完才发现要求不存在的证据。
纯步行配方须显式使用步行验收范围；不得自动删除车辆门槛或把缺失证据当作零违规。


方向接口检查的独立诊断实现与全图基线见 [DF/DG](../audit/road-services-df/README.md)。
接口的多种候选姿态不能被当作互相连接的虚拟节点；两段分别可达不代表能从同一姿态
串成连续行程。保留真实边序列，并将局部道路通行、全镇绕行、实际车主接入分别核验。
新检查目前只输出诊断，尚不授予停车/发布权限。


方向接口的核验还须检查其成员在注册源折线上的位置与朝向，并保留折返/自交时的
多解，不能只用道路 ID 或最近端点分组。源折线距离/标注宽度不替代实测支撑。
接口位于路段另一半只是复核信号，不是新的拒绝阈值；应结合实际连续转向路径解释。
[DU 全图核验](../audit/road-services-du/README.md) 表明当前缺失通路不能主要归因于
端点集合放反，下一步须区分编译碎片、缺失转换与真实地面限制，不能直接减少车流。

### 拒绝原因与派生层复现

支撑检查失败不能直接写成“真实容量不足”。网格接入至少区分坐标/插值边界、缺失高度邻域、已有高度但主体掩码拒绝；路线检查另分离端点、中间足迹和转向约束。诊断结果应与实际准入函数核对，不能另建一个更宽松的“解释器”。

当掩码来自多个条件叠加时，保留父层与构建代码/参数摘要，先重现派生层，再判断道路语义、净空、坡度或边界规则是否合理。条件可重叠，重复采样数不等于独立障碍数；构建可复现不等于场景真实，物理拒绝仍须源重建证据。[DX–DZ 全场证据](../audit/road-services-dz/README.md)展示这一流程，不授予未验证道路通行权。

## 成熟后端接入：转换保真与目的地控制权

SUMO、OpenDRIVE、导航网格等转换产物须与来源分别核验坐标、高程、语义和未知区域。
工具退出成功不等于转换保持了场景；曲线的内部极值也须检查，不能只比较端点。
源高程缺失、关联失败与真实不连通分别记录，不默认补零；发现异常后保留诊断产物，但不进入长时间录制。
原场景全域网格核验与高程过冲实例见 [路线 B 导航报告](../research/route-b-native-navigation-2026-10-27.zh-CN.md)。

行为后端必须声明目标控制权：谁分配目的地、何时认定到达、何种情况重规划或换目标、等待和设施占用如何表示。
后台自动随机改目的地不能被当成原活动成功；物理碰撞被关闭时，也不能据引擎名称声称已有碰撞保障。
支持面、可通行语义、导航侵蚀、局部避让、活动资源与可视骨骼接触是不同的能力，分别提供证据。
组件可独立复用，无须为了使用成熟导航而迁移 Drone4D 渲染或更换真实重建背景。

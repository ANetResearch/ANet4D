# 共享道路交互：下一项通用机制的边界

状态：设计与实验要求，**尚未实现或验收**。依据 AY 全体活动与车辆阻挡证据，
不为某个目标或某个坐标设例外。该工作服务于“环境条件 → 自主活动 → 场景覆盖 → query 验证”主线。

## 要解决的问题

目前车辆会根据实际和预测行人位置停车，行人会根据实际车身避碰。
这两项安全检查不能保证双向、有持续需求的共享道路能够互相放行。
AY 的等待车已经持有当前车辆交通资源，却被多名行人轮流阻挡；
全体位置记录又不支持把所有长行程解释为原地抖动。单独增加车辆预约或移动一名行人，
都不足以证明这类交互解决。

## 环境输入与行为责任

环境提供真实通行空间、道路方向、过街许可、停留禁区和可让行空间。
这些信息可以来自适配器和已核验几何，不要求每条道路手写交通事件。
缺失语义须显式报告，不以“可走”推断“适宜长期占用车道”，也不凭空添加人行道或红绿灯。

引擎负责协调临近的相交/相向运动意图：保持原活动目的，允许短暂让行、绕行、恢复。
其目的不是最短时间出行，而是在实际空间内使多样活动能够持续执行。
物理安全检查始终独立；任何优先权都不能授权穿过已经存在的身体。

## 候选机制

1. 只为临近冲突形成短距离通行走廊与冲突集合；复用已经核验的路径几何和空间索引。
   不预约整个活动或整条街，不每 tick 做全图 A*。
2. 先允许已经位于冲突空间内的主体退出，再决定谁暂缓进入；已有主体不能被冻结在车前。
   面对迎面行人，须先确认其存在可连续到达的让行空间，不能假定降低期望速度即可腾出车道。
3. 临时优先权依据冲突到达顺序和等待年龄，而非人物 ID、query 身份或固定车辆特权。
   资源随实际身体离开释放；目的地改变、取消活动和紧急制动都触发重新核验。
4. 让行结束后恢复原活动和路径，明确记录等待原因、取得/释放通行权、恢复时间。
   如果实际空间无法容纳会车，报告空间/方向约束或选择真实替代路，不能静默停成背景车。

这只是候选方案。先在参数化交互中比较，不直接替换全镇控制器后等待长构建。

## 对照与停止条件

同一冻结几何和种子下，覆盖双向横穿、沿路相向、同向慢行、持续人流、连续车流、
窄路有/无避让空间、路旁停车、进入冲突后意图取消。包含场景旋转、镜像和主体顺序变化，
以排除坐标或身份偶然性。逐步增加流量，区分低于容量时的执行死锁与过载排队。

同时记录安全、双方完成数/通过量、等待分布、长尾、活动恢复、完整路径与规划耗时。
不以平均速度替代完整活动，不用某个固定人口数字证明容量，不要求高流量时永不停车。
若安全改善以另一方永久饥饿为代价，或规划成本增长压倒运动成本，该候选失败。

通过小规模机制对照后，才用冻结的真实镇区完整 1500 秒运行验证；随后重新绑定七条 query。
旧磁带、旧相机见证或局部通过，不能代替新版本全场与任务验收。

## BD 实测更新

[共享道路对照](../audit/shared-street-bd/README.md)证明，基础横穿与双向流动并非全部需要新优先权系统；
已有拥堵绕行能解除参数化道路中的局部相互等待。发现并补齐了主 LifeEngine 向绕行器
传递身体/地面几何的接口，使合法观测位置可以使用现有受限连接器返回规划网络。
因此暂不增加新的交通优先权模块；先验证已有机制完整接入后的实景表现。
这不代表 AY 失败已修复，也不改变本计划对持续流量、公平性和性能的验收要求。

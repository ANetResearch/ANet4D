# 有预算的拥堵绕行

这是通用交通执行能力，改编自 Claude `03ae1c1`，不含场景坐标或目标 ID。
车辆预计将长期等候其他车辆占用的冲突段时，可以沿现有合法有向图寻找替代路径。
找不到路径、绕路成本超过预算或无法安全接续时，保持原路线与正常让行。
不挪动车辆、不新增路面、不改变泊位、车身或碰撞约束。

## 接线与因果关系

`LifeEngine` 在本 tick 接受的世界状态上，先更新占用，再调用
`DrivingRoutes.prepare_revisions(t)`，最后统一绑定活动证据后才生成运动提案。
停车绕行与拥堵绕行共享既有 `revise`：只在未执行的后续路线接续，接续点必须位于
制动距离和已持有冲突段之后；副本控制器与全体预约验证成功后才提交。
目的地不变，历史前缀和当前身体位置不变，活动事件记录替换前后的路线证据。
只统计真实观察到的进展，不以名义到达时间释放资源。

## 运行开销

- 安全检查仍按运动 tick 执行；拥堵判断至多每个仿真秒一轮。
- 每轮最多两个实际改道请求，跨车辆轮转，避免固定排序让末尾车辆一直得不到机会。
- 同一停车点/阻塞车辆集合十秒内不重复搜索，保留已有路径缓存。
- 预期等待十秒以上才考虑，前探不超过制动距离外 80 m；额外路线成本不超过
  预计等待乘巡航速度、且至多 400 m。它们是当前可调策略常数，不是场景容量标准。
- 记录 congestion_rounds、congestion_searches、congestion_revised、congestion_wall_s。
  请求数并不是 A* 展开数，单次搜索耗时仍需在真实图中计量，不能宣称硬实时上界。

当前没有引入 Claude 的单独让行预约策略、私有返家泊位推断或巡游目的地偏好。
这些机制需各自依据 feature 与整体活动证据审查，不能因为绕行样例通过就一起合并。

## 验证边界

84 项相关检查通过，覆盖主运行时接线、连续前缀、绕行/等待选择、费用上限、
搜索频率/轮转、停车绕行、安全合流及活动链证据重绑定。
同一组冻结真实场景的 1500 s 运行仍须完成；不能从合成路口推出镇区容量改善。
道路 feature 的方向接口与实际几何核验仍是独立前提，不靠重规划掩盖输入缺陷。
